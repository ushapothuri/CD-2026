#  Lab Practice 3 —Generating Three-Address Code from an AST

This lab exercise demonstrates how a compiler generates **Three-Address Code (TAC)** from an **Abstract Syntax Tree (AST)**. The AST is traversed in **postorder (bottom-up)** so that the value of each subexpression is computed before it is used by its parent node.

The generated intermediate code is represented in **Quadruple notation of Three-Address Code (TAC)**.

---

# 1. What is Three-Address Code?

**Three-Address Code (TAC)** is an intermediate representation (IR) used by compilers between parsing and machine code generation.

Each TAC instruction contains **at most three addresses**:

* Two source operands
* One destination operand

Complex expressions are broken into a sequence of simple statements using **temporary variables**.

For example,

```text
x = a + b * c
```

is converted into

```text
t1 = b * c
t2 = a + t1
x = t2
```

Instead of evaluating the entire expression at once, the compiler computes one operation at a time.

---

# 2. Why Use Three-Address Code?

Three-address code offers several advantages:

* Simplifies complex expressions.
* Makes compiler optimization easier.
* Is machine-independent.
* Serves as an intermediate step before target code generation.
* Preserves operator precedence and associativity.

Almost every modern compiler internally converts source code into some form of intermediate representation before generating assembly or machine code.

---


# 3. Quadruple Representation

A compiler usually stores TAC internally in a structured form instead of plain text.

One common representation is the **Quadruple**.

Each instruction consists of four fields:

| Operator | Argument 1 | Argument 2 | Result |
| -------- | ---------- | ---------- | ------ |
| op       | arg1       | arg2       | result |

For the previous example, the quadruple table is

| Operator | Arg1 | Arg2 | Result |
| -------- | ---- | ---- | ------ |
| `*`      | `b`  | `c`  | `t1`   |
| `+`      | `a`  | `t1` | `t2`   |
| `=`      | `t2` | —    | `x`    |

The temporary variables (`t1`, `t2`, ...) are automatically generated by the compiler.

---

# 4. AST Traversal Algorithm

The TAC generator performs a **postorder traversal** of the AST.

For every node:

1. Generate code for the left subtree.
2. Generate code for the right subtree.
3. Create a new temporary variable.
4. Emit one quadruple instruction.
5. Return the temporary variable to the parent node.

Leaf nodes (identifiers and constants) simply return their names without generating any code.

This approach naturally respects operator precedence because child nodes are always processed before their parent node.

---

# 5. Complete Example

### Source Program

```text
result = (a + b) * (c - d)
```

### AST

```text
            =
          /   \
     result     *
               / \
              +   -
             / \ / \
            a  b c  d
```

### Three-Address Code

```text
t1 = a + b
t2 = c - d
t3 = t1 * t2
result = t3
```

### Quadruple Representation

| Operator | Arg1 | Arg2 | Result |
| -------- | ---- | ---- | ------ |
| `+`      | a    | b    | t1     |
| `-`      | c    | d    | t2     |
| `*`      | t1   | t2   | t3     |
| `=`      | t3   | —    | result |
